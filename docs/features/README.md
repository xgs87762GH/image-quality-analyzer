## 核心功能

### 1. 图像质量分析

系统可以对图像进行全面的质量评估，包括：

- **模糊度检测**: 使用Laplacian方差算法检测图像清晰度
- **亮度分析**: 计算平均亮度，检测过曝或欠曝
- **信息熵**: 评估图像的信息量和复杂度
- **BRISQUE评分**: 无参考图像质量评估（可选）
- **审美评分**: 基于CLIP模型或AI模型的审美评估（可选）

### 2. 数据库存储

- **SQLite数据库**: 所有分析结果持久化存储
- **自动去重**: 基于文件哈希自动识别重复图像
- **快速查询**: 支持按评级、标签、质量分数查询
- **统计分析**: 自动生成质量统计报告

### 3. 元数据管理

#### XMP元数据写入

- **写入元数据**: 将分析结果写入图像文件的XMP元数据
- **兼容性**: 兼容主流图像管理软件（Lightroom, Bridge等）
- **元数据字段**:
  - Rating: 1-5星评级
  - Label: 质量标签（High/Medium/Low/Very Low）
  - Subject: 关键词列表
  - Description: 详细指标JSON

#### 完整元数据读取

- **读取所有元数据**: 支持读取图像的完整元数据（EXIF、GPS、XMP、IPTC等）
- **分类展示**: 元数据按类别组织（基本信息、相机信息、GPS信息、XMP信息等）
- **优雅降级**: 如果ExifTool不可用，自动使用数据库中的元数据
- **Web界面支持**: 在图像详情页面可以查看完整元数据

## 质量评估

### 评估指标

1. **模糊度 (Blur Score)**
   - 算法: Laplacian方差
   - 范围: 0-∞（越高越清晰）
   - 阈值: < 100 视为模糊

2. **亮度 (Brightness)**
   - 算法: 平均像素强度
   - 范围: 0-255
   - 理想值: 150左右

3. **信息熵 (Entropy)**
   - 算法: 信息熵计算
   - 范围: 0-8
   - 阈值: < 5 视为信息量不足

4. **BRISQUE (可选)**
   - 算法: 无参考图像质量评估
   - 范围: 0-100（越低越好）
   - 需要: OpenCV quality模块

5. **审美评分 (可选)**
   - 方式1: CLIP模型（本地）
   - 方式2: AI模型（GPT-4V, Claude, Gemini, Ollama）
   - 范围: 0-10分

### 综合评分

系统将各项指标归一化到0-100范围后，按权重计算综合质量分数：

```
质量分数 = 模糊度归一化值×权重 + 亮度归一化值×权重 + 熵归一化值×权重 + 审美归一化值×权重
```

**归一化方法**：
- **模糊度**: 基于阈值归一化（阈值通常为100）
- **亮度**: 基于理想值150，考虑容差范围
- **信息熵**: 基于阈值归一化（阈值通常为8）
- **审美评分**: 从0-10映射到0-100

**权重配置**（可在 `utils/constants.py` 中调整）：
- 模糊度: 40% (0.4)
- 亮度: 30% (0.3)
- 信息熵: 30% (0.3)
- 审美评分: 30% (0.3，如果启用)

**阈值配置**：
- 高质量: ≥80分
- 中等质量: 60-79分
- 低质量: 40-59分
- 极低质量: <40分

### 评级和标签

- **1-5星评级**: 根据质量分数自动映射
- **质量标签**: High / Medium / Low / Very Low
- **问题检测**: 自动识别模糊、亮度问题、低熵、高失真等问题

## AI分析

### 支持的AI模型

1. **GPT-4 Vision** (OpenAI)
   - 需要: OpenAI API密钥
   - 特点: 强大的图像理解能力

2. **Claude 3** (Anthropic)
   - 需要: Anthropic API密钥
   - 特点: 优秀的图像分析能力

3. **Gemini Pro Vision** (Google)
   - 需要: Google API密钥
   - 特点: 多模态理解能力

4. **Ollama** (本地)
   - 需要: 本地Ollama服务
   - 推荐模型: llava, qwen2-vl, qwen3-vl
   - 特点: 完全本地化，无需API密钥

### AI分析功能

- **图像描述**: 自动生成图像内容描述
- **质量评估**: AI评估图像质量
- **自定义评估**: 支持自定义评估问题和答案格式
- **审美评分**: 使用AI模型进行审美评估

### 自定义评估问题

支持设置自定义评估问题，例如：
- "是否为手机截图"
- "是否包含人物"
- "拍摄场景类型"

答案格式支持（return_type）：
- **array**: 从预定义选项中选择（如：["是", "否"]、["高", "中", "低"]）
- **float**: 0-1之间的浮点数评分
- **text**: 自由文本描述

详细格式说明请查看 [评估格式说明](../guides/evaluation-format.md)

## 元数据管理

### XMP元数据写入

系统支持将分析结果自动写入图像的XMP元数据，兼容主流图像管理软件。

#### 支持的XMP标签

系统使用标准XMP标签，确保最佳兼容性：

**XMP Core标签**（最常用，兼容性最好）：
- `xmp:Rating` - 星级评分 (1-5)，支持Lightroom、Capture One、Luminar等
- `xmp:Label` - 颜色标签，用于质量分类
- `xmp:MetadataDate` - 元数据修改日期

**Dublin Core标签**（标准元数据）：
- `dc:Subject` - 关键词/主题（使用追加模式，保留原有关键词）
- `dc:Description` - 描述信息（追加质量分析摘要，不覆盖原有描述）
- ⚠️ **不写入** `dc:Title` - 保护原有标题
- ⚠️ **不写入** `dc:Creator` - 保护原有作者信息

**IPTC Core标签**（新闻摄影常用）：
- `Iptc4xmpCore:Keywords` - 关键词数组格式（某些软件需要）

#### 关键词生成

系统通过多种方式生成关键词：

1. **质量分析关键词**：基于图像质量指标自动生成
   - 质量标签（HighQuality, MediumQuality等）
   - 问题检测（blurry, brightness_issue, low_entropy等）

2. **AI分析关键词**：从AI分析文本中智能提取
   - 自动识别图像内容相关的关键词
   - 支持中文和英文关键词提取
   - 从评估结果中提取结构化关键词

3. **关键词合并**：自动合并并去重，确保XMP中的关键词丰富且准确

#### 软件兼容性

**完全兼容** ⭐⭐⭐⭐⭐：
- **Adobe Lightroom** - 完整支持所有XMP标签，可读取评分、标签、关键词、描述
- **Adobe Bridge** - 作为Adobe生态的一部分，完整支持

**良好兼容** ⭐⭐⭐⭐：
- **Capture One** - 支持核心标签（评分、标签、关键词、描述）
- **ON1 Photo RAW** - 支持关键词树、描述、评分、颜色标签

**基础兼容** ⭐⭐⭐：
- **Luminar** - 支持基础标签（标题、描述、标签、评分、关键词）
- **XnView** - 支持大部分XMP标准标签
- **digiKam** - 支持XMP标准标签
- **Photo Mechanic** - 支持XMP元数据读写

#### 元数据保护 ⚠️ 重要

**系统严格保护原有元数据，绝对不会覆盖或影响：**

- ✅ **个人信息**：作者、版权、联系方式等
- ✅ **时间信息**：拍摄时间、创建时间、修改时间等（仅更新MetadataDate）
- ✅ **地点信息**：GPS坐标、地理位置、地址等
- ✅ **摄影参数**：EXIF数据（ISO、光圈、快门速度、焦距、设备型号、镜头信息等）
- ✅ **编辑历史**：原始编辑记录、工作流程数据等

**系统仅写入以下质量分析相关字段：**
- `xmp:Rating` - 质量评分（使用追加模式，不覆盖）
- `xmp:Label` - 质量标签（使用追加模式，不覆盖）
- `dc:Subject` - 分析关键词（使用追加模式，保留原有关键词）
- `Iptc4xmpCore:Keywords` - 关键词数组（使用追加模式）
- `dc:Description` - 质量分析描述（追加到现有描述后，使用`[质量分析]`标记）
- `xmp:MetadataDate` - 元数据修改日期（仅更新此字段）

**技术保障：**
- 使用ExifTool的`-preserve`选项保护所有现有元数据
- 使用`+=`追加模式而非`=`覆盖模式
- 仅操作预定义的安全字段白名单

#### ExifTool安装（自动下载）

**系统会在首次启动时自动下载ExifTool，无需手动操作！**

- 启动项目时，系统会自动检测ExifTool
- 如果未找到，会自动从 https://exiftool.org/ 下载对应平台版本
- 下载后自动解压到 `exiftool/` 目录
- 完全自动化，用户无需任何操作

**系统检测优先级：**
1. 项目内的 `exiftool/` 目录（自动下载）
2. 系统PATH中的ExifTool（如果已安装）

**手动安装（可选）**：
如果自动下载失败，可以手动安装：
- **Windows**: 下载并添加到系统PATH
- **macOS**: `brew install exiftool`
- **Linux**: `sudo apt-get install libimage-exiftool-perl`

#### 使用建议

1. **跨平台兼容**：使用标准XMP标签（评分、关键词、描述）确保最佳兼容性
2. **关键词管理**：启用AI分析可自动生成丰富的关键词，提升图像可搜索性
3. **数据备份**：系统默认创建备份（.bak文件），可在设置中关闭
4. **ExifTool安装**：推荐下载到项目目录，无需系统安装，便于部署
5. **安全可靠**：系统设计确保不会丢失或覆盖任何原有元数据

## 回收站功能

### 功能特性

回收站功能参考 digiKam 等专业图像管理软件的实现方式，提供安全可靠的文件删除和恢复机制。

#### 1. 软删除（移动到回收站）

- **文件移动**: 删除的图像文件移动到回收站目录（不真正删除）
- **保留目录结构**: 支持保留原始目录结构，便于组织和管理
- **跨平台支持**: 自动适配 Windows、macOS、Linux 不同平台的路径格式
- **路径处理**: 
  - Windows: 自动处理驱动器号（如 `F:\` → `F_`）
  - Linux/macOS: 正确处理绝对路径（从 `/` 开始）
- **文件冲突处理**: 自动处理重名文件，添加序号避免覆盖
- **删除时间记录**: 在数据库中记录删除时间，便于查询和排序

#### 2. 恢复功能

- **自动恢复**: 从回收站恢复图像，自动移回原始位置
- **路径冲突处理**: 如果原位置已有同名文件，自动重命名避免覆盖
- **数据库更新**: 恢复时自动清除删除标记，更新文件路径

#### 3. 永久删除

- **确认对话框**: 使用自定义确认对话框，确保用户明确操作后果
- **安全删除**: 真正删除图像文件和相关数据库记录
- **批量支持**: 支持批量永久删除，提高操作效率
- **关联数据清理**: 自动删除关联的质量评估和元数据记录

#### 4. 回收站配置

- **自定义路径**: 支持自定义回收站目录路径
- **默认路径**: 默认使用 `用户目录/ImageQualityAnalyzer/Trash`
- **目录结构保留**: 可在设置中选择是否保留原始目录结构
- **自动创建**: 回收站目录不存在时自动创建

### 技术实现

#### TrashManager 服务

回收站功能由 `TrashManager` 服务类统一管理（高内聚设计）：

- **职责集中**: 所有回收站相关操作集中在此类
- **跨平台兼容**: 自动处理不同操作系统的路径差异
- **错误处理**: 完善的异常处理和日志记录
- **依赖注入**: 通过配置注入，符合低耦合原则

#### 核心方法

- `move_to_trash()`: 移动文件到回收站
- `restore_from_trash()`: 从回收站恢复文件
- `calculate_trash_path()`: 计算回收站路径（跨平台）
- `resolve_file_conflict()`: 解决文件冲突

### 使用场景

- **误删恢复**: 误删图像后可以快速恢复
- **批量清理**: 批量删除不需要的图像，后续决定是否永久删除
- **临时删除**: 临时移除图像，保留恢复选项
- **空间管理**: 定期清理回收站，释放磁盘空间
